# QR codes for field service

Each QR code below resolves to a **permanent** URL on the deployed

documentation site. Nothing here points at a preview build or a local address,

so a label printed today keeps working indefinitely.

The site is built with `use_directory_urls: false`, so page addresses are flat

`.html` files.

!!! info "Where the codes come from"

    Every image is generated by `scripts/generate_qr_codes.py` and verified in

    CI. The script fails the build if an image does not match the URL it is

    supposed to encode, so a stale code cannot ship.

## Printable node labels

The layout below is the label artwork. The QR is 2.3 in (about 58 mm) square in

CSS units, which stays reliably scannable on a laminated field label.

Print at **100 % scale**. Do not use "fit to page", and do not crop through the

quiet zone around the QR code.

### Label guidance

| Consideration | Guidance |

|---|---|

| Material | Weather-resistant vinyl or laminated paper; the enclosure environment is not verified |

| Mounting | Fix the label to the enclosure, not to a sensor cable |

| Legibility | Keep the quiet zone (blank margin) around the code; do not place the label over a window or transparent window |

| Failure of the code | Every node page is reachable from [Documentation home](../index.md), and each page names its own firmware file and commit |

!!! warning "The QR code is an aid, not the source of truth"

    A node's identity cannot be confirmed from telemetry. The protocol carries

    no node address, so two physically similar nodes exchanged by mistake are

    not detectable from the data. Confirm identity physically and by the

    observables in [Node identification](node-identification.md).

## Regenerating the codes

```bash

python scripts/generate_qr_codes.py          # regenerate

python scripts/generate_qr_codes.py --check  # verify nothing is stale

```

Destination URLs are declared once, in `TARGETS` inside the script, and written

to `docs/assets/qr/qr-targets.yml`. That file is what CI validates, so changing

a destination in one place updates the manifest that the validator enforces.
