## Findings produced by this audit

The audit that produced this documentation build surfaced several findings that
were not previously written down anywhere. They are recorded here because they
are verifiable facts about the source, not interpretations.

| # | Finding | Where |
|---|---|---|
| 1 | Node 2's reverse-telemetry parser looks for `\|FR:`, but Node 3 emits `\|FLM:`; the parser therefore cannot succeed, and the struct it would populate is not read anywhere | `Node2.ino` 240–254 versus `Node3.ino` 128 |
| 2 | `Node4_SMTP` does not clean the upstream packet, so the controller receives Node 2's ambient pair rather than Node 4's | absent from `Node4_SMTP.ino`; present at `Node4.ino` 1082–1085 |
| 3 | `Node4_SMTP` reintroduces a 5 V-referenced turbidity conversion via `turbVolt5V = turbVolt * (5.0f / 3.3f)`, which `Node4`'s comments explicitly reject | `Node4_SMTP.ino` 214–217 |
| 4 | `phRaw`, `turbRaw`, `ecRaw` are computed every cycle and never used | `Node4.ino` 462, 515, 588 |
| 5 | `adcToVoltage` accumulates millivolts, ignores them, and returns a 3.3 V-referenced value; it has no call site | `Node4.ino` 219–241 |
| 6 | Node 3 marks every flow sample valid, so a disconnected flow sensor is indistinguishable from no flow | `Node3.ino` 62 |
| 7 | Node 4's display prints stored values with no invalid-value substitution, so an invalid reading looks like a valid zero | `node4-lcd-task` |
| 8 | The 45 °C / 80 % thresholds are commented as Node 2 enclosure limits but are applied on Node 1's LCD status line | `Node1.ino` 26–28 versus `Task_LCD_Node1` |
| 9 | The `SET:` console keywords are case-sensitive while `HELP`, `STATUS` and `RESET` are not | `Node4.ino` 727, 762, 817, 855, 884, 913 |
| 10 | `Serial.readStringUntil('\n')` blocks Node 4's UART task, so an unterminated command stalls telemetry forwarding | `Node4.ino` 722–723 |

All ten are carried into
[Known Limitations](known-limitations.md).

## What remains unverified

Grouped by the reason it is unverified.

**Because it is not in the repository at all**

* ESP32 board variant and devkit model.
* Power supply voltage, current draw, regulator part numbers, battery or solar
  topology.
* Enclosure dimensions, materials, IP rating.
* Sensor manufacturer and part number for dissolved oxygen, flow, pH and
  conductivity.
* Cable types, lengths, gauges, connector pinouts.
* Schematics, wiring diagrams, PCB files.
* Hardware photographs.
* Licence file.
* Library versions and Arduino-ESP32 core version.

**Because it requires measurement**

* Accuracy, resolution, repeatability and drift of any sensor.
* Whether the derived maxima (for example the Node 1 doubled volume) match the
  physical tanks.
* Actual task jitter, stack headroom or CPU load.
* Behaviour under a sustained chain break, brownout or noisy supply.
* Whether the ultrasonic, DO, pH, turbidity or EC conversions agree with
  reference instruments.

**Because it requires knowledge held outside the repository**

* Which firmware commit is on any deployed node.
* The downstream controller's firmware and its expectations of field names.
* The deployed network and mailbox configuration for the SMTP variant.
* Project-level facts such as duration, funding and consortium composition —
  taken from the official site, and to be re-verified before publication. See
  [Official Project Sources](../references/official-project-sources.md)).

**Because it has not been done**

* Any execution of the procedures on
  [Hardware Validation](hardware-validation.md).
* Any of the tests proposed in [Test Strategy](test-strategy.md)).
* Any standards-conformance assessment. None is claimed; see
  [Standards](../references/standards.md)).

## Re-running this verification

```bash
git submodule update --init --recursive
git -C _external/Cirqua-firmware rev-parse HEAD        # expect db6d9b8...
git -C _external/Cirqua-firmware status --porcelain    # expect no output
python scripts/extract_code_snippets.py --check        # expect exit 0
python scripts/extract_code_snippets.py                # regenerate if needed
mkdocs build --strict
```

If the commit does not match, or if the staleness check reports a difference,
**do not rely on any line number, constant or format on these pages** until the
pin has been moved and the affected pages re-audited. See
[Repository](../firmware/repository.md) for the full update procedure.
